# SB Front End 4A — BEACON+ and community detail polish

## Delivered presentation

- Home and the owner's Profile have a labeled, 44px BEACON+ header button opening `/settings/premium`. Calendar, Inbox and Settings remain accessible. Other people's profiles, chats, editors and community headers do not acquire a global promotion.
- Profile separates membership with thin theme-colored horizontal rules and measured spacing; BEACON+ benefit groups use short accent rules and quiet dividers. Profile shows the resolved personal tier and relevant Boost allowance. Premium leads with actual membership and three practical benefit groups, then explains Squad sharing before the comparison and membership details. Pricing and purchase-availability boundaries remain explicit.
- Expanded advanced settings identify required Plus/Pro, actual inclusion, shared Squad access, simulation, grace and unsupported features. Existing Free functionality and management permissions remain unchanged. Supported locked settings offer a benefit link; included settings offer membership details.
- The Squad summary uses 2/4 qualification thresholds, capped progress and separate effective grace status. Personal allowances remain canonical 2/5; no Beacon Boosts are introduced.
- Existing compact community cards, relationship rows and virtualized directories use theme surfaces, gentle borders, rounded corners, 44px community icons, descriptions and counts. A lightweight Joined label leaves room for names to wrap. Custom Squad icons come from independently authorized records.
- Members and invitations use privacy-aware avatars and compact readable rows. Management actions wrap together and retain their existing permission checks and confirmations. Member search is available in small populated directories too.
- Community Beacon previews/history use real category/custom icons, timing, status, known parent context and the canonical permitted attendance preview. Existing public previews retain their safe summary transport. Compact Beacon cards reused by community previews now include the actual Beacon icon.
- Settings categories share relevant icons, short descriptions and the same row hierarchy. Membership/advanced actions are visually separated. Existing forms, guarded drafts and routes remain authoritative.

## In Common

`selectCommunityInCommon` uses only the current viewer's authorized snapshot. Target-community membership, profile visibility, accepted friendship, independent child membership, blocks and bans are checked before inclusion. Public summary access alone does not unlock a private overlap directory.

Previews prioritize Friends here, Squads in common for Organizations, and Organizations in common for Networks. Shared Beacon overlap requires hosting or approved Going plus existing Beacon read access and an explicit audience/association. Invitations and unapproved attendance never count. A compact shared-Beacon entry opens grouped real rows rather than duplicating the overview's activity list. Expanded results support search and incremental reveal. Viewer/session keys reset private UI state.

Optional interests are omitted because this pass has no canonical community-interest comparison. Missing/empty overlap is omitted. No extra per-row requests, synthetic counts or membership inheritance are introduced; existing directory paging and stale-response guards remain.
